# استخدام كلمة "private" في لغة سكالا: تعريف شامل

## ملخص
تُستخدم الكلمة المحجوزة "private" في لغة سكالا لتحديد نطاق الوصول إلى الأعضاء (المتغيرات والدوال) داخل الكلاسات. يسمح هذا بتعزيز الأمان وتقليل التعقيد عن طريق إخفاء التفاصيل الداخلية عن الكود الخارجي.

## الوثائق
تُستخدم كلمة "private" لتحديد الأعضاء التي يمكن الوصول إليها فقط من داخل الكلاس الذي تم تعريفها فيه. هذه الممارسة تعزز مفهوم الت encapsulation في البرمجة الكائنية، مما يسمح بحماية البيانات وتخفيف التداخل بين الكلاسات المختلفة.

### الاستخدام
يمكن استخدام "private" كما يلي:
- **في تعريف المتغيرات**: عندما تحتاج إلى إخفاء المتغيرات عن الكود الخارجي.
- **في تعريف الدوال**: عندما تريد أن تكون الدالة متاحة فقط داخل الكلاس.

### التفاصيل
- يتم تعريف الأعضاء الخاصة باستخدام الكلمة المفتاحية "private" قبل تعريف المتغير أو الدالة.
- الأعضاء الخاصة لا يمكن الوصول إليها مباشرة من خارج الكلاس.
- يمكن للكلاسات الفرعية (subclasses) الوصول إلى الأعضاء الخاصة إذا كانت موجودة في نفس الكلاس.

## أمثلة
### مثال 1: استخدام "private" مع المتغيرات
```scala
class User {
  private var name: String = "غير معروف"

  def getName: String = name
}

val user = new User()
println(user.getName) // يطبع "غير معروف"
// println(user.name) // سيؤدي إلى خطأ في التجميع لأن name خاص
```

### مثال 2: استخدام "private" مع الدوال
```scala
class Calculator {
  private def add(a: Int, b: Int): Int = a + b

  def calculate(a: Int, b: Int): Int = add(a, b)
}

val calc = new Calculator()
println(calc.calculate(5, 3)) // يطبع 8
// println(calc.add(5, 3)) // سيؤدي إلى خطأ في التجميع لأن add خاص
```

## الشرح
- **المزالق الشائعة**: قد يعتقد بعض المطورين أنهم يستطيعون الوصول إلى الأعضاء الخاصة من خلال الكلاسات الفرعية. يجب أن يكونوا واعين أن الأعضاء الخاصة تظل محجوبة.
- **ملاحظات إضافية**: استخدام "private" بشكل مفرط قد يجعل الكود معقدًا. من الضروري إيجاد توازن بين إخفاء المعلومات ومرونة الوصول للأعضاء.

## ملخص بعبارة واحدة
تستخدم الكلمة "private" في سكالا لتقييد الوصول إلى الأعضاء داخل الكلاس، مما يعزز الأمان ويدعم مفهوم الت encapsulation.
