# الحماية في Scala: استخدام كلمة "protected"

## ملخص
كلمة "protected" في Scala تُستخدم لتحديد مستوى الوصول للمتغيرات والطرق في الصفوف. تُتيح هذه الكلمة للصفوف الفرعية الوصول إلى العناصر المحمية من الصف الأب، مما يسهل إعادة استخدام الكود وتعزيز الهيكلية البرمجية.

## الوثائق
تُستخدم كلمة "protected" في Scala كنوع من أنواع التحكم في الوصول، مما يسمح للصفوف الفرعية بالوصول إلى أعضاء الصف الأب. الأعضاء المعنونة بـ "protected" تكون متاحة فقط ضمن الصف الأب والصفوف الفرعية له، ولكنها غير متاحة من خارج ذلك النطاق. 

### الاستخدام
- يمكن استخدام "protected" مع المتغيرات والطرق في الصفوف.
- تُعتبر "protected" أقل تقييداً من "private"، حيث تسمح بالوصول من الصفوف الفرعية.
  
### تفاصيل
- الأعضاء المحمية يمكن الوصول إليها فقط داخل الصف الأب أو الصفوف التي ترث منه.
- تسمح "protected" بتعزيز مفهوم الوراثة وتوفير كود مشترك بين الصفوف.
- يمكن أن تُستخدم "protected" في الصفوف الأساسية كما في الصفوف المدمجة (traits).

## الأمثلة
### مثال 1: استخدام "protected" في الصفوف
```scala
class Parent {
  protected def showMessage(): String = "رسالة محمية"
}

class Child extends Parent {
  def displayMessage(): String = showMessage()
}

val child = new Child
println(child.displayMessage()) // مخرجات: رسالة محمية
```

### مثال 2: استخدام "protected" مع المتغيرات
```scala
class Base {
  protected var number: Int = 42
}

class Derived extends Base {
  def getNumber: Int = number
}

val derived = new Derived
println(derived.getNumber) // مخرجات: 42
```

## الشرح
### الأخطاء الشائعة
- محاولة الوصول إلى الأعضاء المحمية من كائن ليس من الصف الأب أو الصف الفرعي.
- عدم فهم الفرق بين "protected" و"private" مما يؤدي إلى مشاكل في التصميم.

### ملاحظات إضافية
- يمكن استخدام "protected" في الصفوف المدمجة، مما يسمح بتعزيز مرونة الكود.
- يجب توخي الحذر عند استخدام "protected" لتجنب الكشف عن تفاصيل التنفيذ للصفوف غير ذات الصلة.

## ملخص بجملة واحدة
كلمة "protected" في Scala تُستخدم للتحكم في الوصول للأعضاء بين الصفوف الأب والصفوف الفرعية، مما يُعزز من إعادة استخدام الكود.
